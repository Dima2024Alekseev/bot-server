# VPS Telegram bot

Бот предназначен для Linux VPS с PM2 и управляет одним приложением PM2. Команды доступны только двум указанным администраторам в личных чатах. Бот вызывает только фиксированные команды PM2 для заданного имени процесса; произвольные команды ОС через Telegram не выполняются.

## Как узнать имя приложения в PM2

Подключитесь к VPS под тем же Linux-пользователем, от которого запущено серверное приложение, и выполните:

```sh
pm2 list
```

Скопируйте значение из столбца `name` нужной строки. Например, для команды запуска `pm2 start server.js --name game-server` укажите `game-server`. Бот не сможет управлять процессом, если запущен под другим Linux-пользователем или подключён к другому PM2 daemon.

## Настройка

1. Установите Node.js 18 или новее и PM2 для пользователя, который управляет приложением.
2. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен Telegram-бота;
   - `ADMIN_CHAT_IDS` — два Telegram chat ID через запятую;
   - `PM2_PROCESS_NAME` — точное имя из столбца `name` команды `pm2 list`;
   - `HEALTH_CHECK_URL` — необязательный URL HTTP/HTTPS health-check вашего приложения;
   - `MONITOR_DISK_PATH` — путь для проверки свободного места (по умолчанию `/`);
   - `CPU_ALERT_PERCENT`, `MEMORY_ALERT_PERCENT` — пороги тревоги (по умолчанию 90%);
   - `DISK_FREE_ALERT_PERCENT` — порог тревоги свободного места (по умолчанию 10%).
3. Установите зависимости и запустите бота от того же Linux-пользователя, что запускает сервер:

   ```sh
   npm install
   npm start
   ```

Не запускайте бота от `root`. Если используете нестандартный `PM2_HOME`, задайте его и для процесса бота, чтобы он подключался к тому же PM2 daemon.

Файл `.env` не следует добавлять в Git или пересылать в чаты. Наблюдения сохраняются в `data/reminders.json`, журнал администраторских действий — в `data/admin-actions.jsonl`; сохраняйте каталог `data` при обновлении проекта.

## Команды

- `/start` — показать панель с кнопками;
- `/status` — состояние приложения PM2;
- `/logs` или `/logs 50` — последние строки логов (до 100);
- `/resources` — текущие CPU/RAM/диск и пороги;
- `/actions` — последние действия администраторов;
- `/startserver` — запустить приложение, сохранённое в PM2;
- `/stopserver` — остановить приложение;
- `/restartserver` — перезапустить приложение;
- кнопка `⏰ Напоминание` — включить автоматическое наблюдение за сервером на 10 минут, 30 минут, 1 час или 1,5 часа. Текст вводить не нужно;
- `/reminders` — показать свои напоминания;
- `/cancelreminder ID` — отменить своё напоминание.

Команда запуска использует `pm2 restart` для выбранного приложения: запись приложения должна оставаться в PM2 (не удаляйте её через `pm2 delete`). Если процесс остановлен, но сохранён в PM2, эта команда запустит его снова.

Кнопки остановки и перезапуска запрашивают подтверждение перед выполнением.

Каждый администратор включает наблюдение независимо: срочные уведомления, сообщения о восстановлении и итог отправляются только ему. Повторный выбор интервала заменяет только его собственное активное наблюдение.

Во время наблюдения каждые 30 секунд проверяются состояние PM2, последние 100 строк логов, CPU/RAM/свободное место на диске и, если задан `HEALTH_CHECK_URL`, доступность HTTP endpoint. По умолчанию тревоги по ресурсам срабатывают при CPU/RAM от 90% и свободном месте на диске не более 10%. Пороги можно изменить переменными окружения. Проверяются маркеры `ERROR`, `FATAL`, `CRITICAL`, ошибки JavaScript, `Unhandled exception/rejection`, `EADDRINUSE`, падения и аварийные статусы PM2. Одинаковые сигналы не отправляются повторно на каждом цикле; повторения группируются в итоговом сообщении. Когда PM2/ресурс/HTTP endpoint восстанавливается, администратор получает отдельное сообщение. Старые совпадения логов при включении наблюдения также показываются сразу, если найдены. «Незамедлительно» означает в пределах интервала опроса — обычно до 30 секунд.

По истечении интервала бот отправит итог: «Никаких проблем с сервером не обнаружено» либо найденные проблемы и метрики. Если VPS или бот выключен, итоговая проверка произойдёт после запуска. Успешные и неуспешные команды запуска/остановки/перезапуска записываются локально в `data/admin-actions.jsonl` и доступны администраторам через кнопку «🧾 Журнал действий» или `/actions`.
